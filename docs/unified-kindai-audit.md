**Exact provider selection.** `server/_core/llm.ts:298` (`canUseOpenAIResponses`) requires all four conditions: a truthy `ENV.openAiApiKey`; no tools or an empty tools array; at least one image/file content part in any message; no message with role `tool` or `function`. If true, `invokeLLM` at line 536 returns the OpenAI call directly. The Responses URL is fixed to `https://api.openai.com/v1/responses`. `buildOpenAIResponsesPayload` at line 392 selects `ENV.openAiModel || "gpt-5.5"`, converts system text to instructions, maps media to `input_image`/`input_file`, carries structured-output schemas when requested, and selects reasoning effort from the thinking budget for supported model names. Output-token limit uses `maxTokens`, then `max_tokens`, then 32768. Fetch has a 120-second abort timer; that timer is cleared when fetch returns headers, before response-body decoding. Non-2xx, incomplete output, refusal and empty text throw. There is **no OpenAI-to-Forge error fallback**.

Otherwise `assertApiKey` at line 219 requires `BUILT_IN_FORGE_API_KEY`. The Forge URL is `BUILT_IN_FORGE_API_URL` plus `/v1/chat/completions`, or the Manus Forge default. The payload model is hardcoded `gemini-2.5-flash`, output limit hardcoded 32768, thinking budget supplied or 128. Tools and normalized tool-choice values are forwarded; execution occurs in the caller, not llm.ts. Forge fetch has a 90-second timer with the same headers/body limitation. `server/_core/env.ts:143` maps `OPENAI_API_KEY`/`OPENAI_MODEL`; Forge mappings are in the same ENV object. OpenAI-only credentials therefore do not support text takeoff, tool chat, or the text-only stages of orchestration. Missing both keys fails before a model call. No model default was changed in this patch.

**Active calls.** `server/_core/index.ts` mounts `appRouter` and `orchestratedTakeoffRouter`.

- `server/routers/ai.ts`: `visionTakeoff` sends one media URL; `visionTakeoffMultiPage` groups URL entries into batches of five, then merges; `analyzePlan` sends text. Each calls `invokeLLM`. Supplier extraction and compliance review also use it but are separate workflows.
- `server/routes/orchestratedTakeoff.ts`: the active `AITakeoff` page uses this stream. Steps 1 and 2 include plan media in vision mode; pricing, business-rule review and optional anomaly cross-check are text-only. Thus one vision job can require **both** OpenAI and Forge. Cross-check failure is caught and permits completion; main-step failure rejects the job. Step 5 assembles results without another model call.
- `server/routers/estimateAgent.ts:201`: up to three tool-call iterations, then a summary if needed. Tool requests go through Forge. Add/update tool dispatch now uses the same transactional edit helper; AI-requested deletion is refused and directs the user to the explicit delete control, matching AGENTS.md.
- `server/routers/demo.ts`: baseline public real-model demos could bypass the free offer. This branch retains sample scenarios but rejects supplied drawings/job descriptions on the public demo endpoint.

**Media handling.** Baseline uploads decoded base64 (32 MB per file), converted HEIC/HEIF to JPEG and stored files; extension-derived URLs reached `server/_core/mediaInputs.ts`. A `.pdf` pathname maps to `file_url` with PDF MIME; other URLs become high-detail images. There is no Node-path OCR, vector-geometry extraction, scale calibration or PDF rasterization. Python/Tesseract references in the separate backend/Dockerfile do not establish that they run in this Express pipeline. A URL entry was counted as a page even if it contained a whole multipage PDF.

The patch's `server/planPreparation.ts` parses PDFs with pdf-lib, copies only the user-selected 1-based page when supplied, preserves vector content, and records true page count in `plan_uploads`. It validates supported image signatures after HEIC conversion. This is page selection, **not OCR or proven geometric measurement**. Pro batch endpoints can still accept whole PDFs; model-provider handling of their internal pages has not been benchmarked.

# B. CONTRACTOR CORRECTION LOOP

**Before.** `EstimateBuilder` called add/update/delete and then a second `recalculate` mutation. Those writes and query invalidations were independent. Update persisted the active line item, but looked it up by item ID alone after authorizing a caller-supplied estimate. Audit insertion happened afterward and swallowed errors. Add/delete did not record matching audit events. `corrections.recordCorrection`/`batchRecord` only inserted historical records; they did not alter active items or totals. Some later prompts consume correction history; that is prompt context, not training or guaranteed learning. The UI's old “add AI items” action could duplicate items already persisted by takeoff.

PDF export read **persisted line_items and estimate totals**, not original raw AI items. That was the correct data source but two uncoordinated reads could combine new rows with old totals. No version guard or draft-export guard proved the PDF matched what the contractor reviewed.

**After.** `client/src/pages/EstimateBuilder.tsx` loads `getWithLineItems` as a single snapshot. `saveEditing` retains the version at the start of editing. Existing `estimates.addLineItem`, `updateLineItem`, and `deleteLineItem` delegate to `server/estimateEdits.ts:30`:

1. Start a DB transaction and lock the owned estimate row.
2. Reject missing ownership or an unexpected version with NOT_FOUND/CONFLICT.
3. For update/delete, locate the item with **both** item ID and estimate ID.
4. Validate fields; persist the mutation; record before/after snapshot plus changed-field events; recompute rows and totals; increment the existing estimate version; invalidate the cached PDF URL.
5. Commit together and return canonical estimate, items, totals and version. Any audit or totals failure rolls everything back.
6. `acceptSaved` writes canonical query-cache data and invalidates dependent estimates/assurance queries. There is no second recalculation request after saving an item.

Quantity is positive, at most three decimal places; zero rate is allowed, negative rates/quantities and non-finite numbers are rejected. Rates have two decimal places. Waste is 0–100%, two decimals, and manually editable nonzero waste is limited to Materials. The existing `margin` field retains its established meaning: **cost markup**, not gross-profit margin. Its validated maximum is 999.99%. These are explicit product rules, not inferred construction measurement standards.

`server/estimatePricing.ts` uses scaled integer quantities, integer cents and basis points with BigInt for authoritative arithmetic. Decimal.js only parses exact decimal representations and normalizes extracted row precision. Each waste-adjusted line rounds half-up to cents; line cents are summed; markup is applied once and rounded; 10% GST is computed once on the marked-up subtotal and rounded; total is integer subtotal cents plus GST cents. Rates are **exclusive of GST**. Returned and stored money remains two-decimal strings compatible with existing MySQL columns. Subscription GST settings are a separate unresolved commercial decision.

Save errors retain form values. A conflict explicitly loads the current saved version without discarding the draft, displays current saved values and requires another user save. Open or retained unsaved item drafts block PDF export and quote-link initiation. Browser reload/close receives an unsaved-change warning; drafts are not durable offline storage.

`estimates.generatePdf` authorizes Pro/legacy-paid access and owner/version, captures rows and canonical prices under the estimate lock, renders the captured array, and only attaches the generated URL if that version is still current. The response includes snapshot version and exact totals. It never falls back to `aiTakeoffData`. The PDF labels subtotal, GST and inclusive total; markup is labelled as already included rather than visually added twice. User text is HTML-escaped and script execution is disabled. Remote brand-logo fetching still needs deployment egress hardening. A version-changing edit during rendering makes attachment fail clearly; an uploaded but unattached PDF may need later cleanup.

`aiTakeoffData` remains the original extraction. Successful jobs preserve it; rescanning an already-extracted estimate requires a new estimate. Audit `aiValue` is a legacy column name: for subsequent edits it contains the **previous saved value**, not necessarily original AI evidence; the event reason says so.
